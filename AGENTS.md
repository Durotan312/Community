# Для AI-агентов и людей, которые меняют этот код

Это внутренний портал компании: Flask + SQLite + чистый JavaScript, без сборки. Всё, что здесь лежит, — код. Данные, ключи и внутреннее описание компании живут в закрытом репозитории и на сервере, сюда не попадают.

## Как устроено

- `app.py` — весь бэкенд: схема базы (словарь `SCHEMA`, миграция добавлением колонок), REST API под `/api/...`, AI-помощник «Connect AI».
- `templates/index.html` — единственная страница, только каркас.
- `static/app.js` — весь фронтенд: роутинг по `data-view`, рендер разделов; `static/style.css` — все стили.
- Новый раздел = запись в `SCHEMA` + пара роутов по образцу соседних + рендер в `app.js` + стили. Другой способ не изобретать.
- Права на кнопки задаёт `UI_RULES` в `app.js`; права на адреса — `require_auth`, `USER_WRITABLE`, `HR_WRITABLE_PREFIX` в `app.py`. Новая кнопка редактирования без правила в `UI_RULES` будет видна всем.
- Вывод в HTML — только через `escapeHtml`; значение внутри `onclick` — только через `jsArg`.

## Правила, которые нельзя нарушать

1. Интерфейс по-русски. Комментарии в коде — тоже.
2. Без эмодзи в интерфейсе: значки только из набора `ICONS` (`ico('name')`). Эмодзи допустимы только в текстах для Telegram в `app.py`.
3. Без подсказок и примеров в интерфейсе: никаких «Например: …», пояснений под полями и под пустыми списками. Плейсхолдеры только функциональные («Поиск…»).
4. AI-помощник зовётся «Connect AI»; название поставщика модели в текстах для пользователя не упоминать.
5. Тексты, которые дал владелец портала, не переписывать своими словами.
6. Это внутренний портал для сотрудников, не сайт для клиентов: никаких рекламных страниц.
7. Всплывающие окна — через `openModal` с разметкой `.modal`.

## Как предлагать изменения

- Работай в ветке и открывай pull request в `master`. Опиши простыми словами, что изменено и зачем, — владелец не программист.
- Перед pull request запусти `python checks/rules.py` (правила выше) и `python checks/ci_smoke.py` (портал запускается). На GitHub они запускаются сами; красный результат — pull request не принимается.
- Изменение в коде сопровождай строкой в описании pull request: что и зачем. Хвосты и недоделанное — тоже в описание.
- Ничего не попадает на сайт без подтверждения владельца: он принимает pull request одной кнопкой.
- Не добавляй в репозиторий ключи, пароли, базы данных, загруженные файлы и личные данные людей.
